# Техническое задание WristLens 0.2

## Цель

Управление камерой обычного Android-телефона с Galaxy Watch Ultra/Wear OS: живой видоискатель, фото и видео, параметры камеры, собственная галерея и перенос оригиналов. Исходная диагностированная пара: Infinix X678B, Android 14/API 34, и Galaxy Watch Ultra 2025.

## Требования и реализация

| Требование | Реализация |
|---|---|
| Живой поток | JPEG через Wearable ChannelClient, один отправляемый и один заменяемый кадр; ACK отображения |
| Размер потока | Не выше пикселей дисплея часов по обеим осям после ориентации; без увеличения |
| Круглый экран | PreviewView center-crop, RoundHud drawTextOnPath, прозрачные IconButton, круглое серое launcher-изображение |
| Основные действия | Фото, старт/пауза/продолжение/стоп видео, фото во время видео |
| Серия | Удержание от 350 мс; настраиваемый предел до 30 кадров, максимум 15 с, heartbeat каждые 250 мс, lease 1200 мс |
| Защита от перестановки | Завершённые hold-ID не запускаются повторно; обычные команды имеют ID и журнал ACK |
| Таймеры | Фото/видео отдельно 0–60 с; отмена; таймер серии только перед первым кадром |
| Камеры и параметры | Список CameraManager; поддерживаемые вспышка, ручной/точечный/автофокус, зум, размеры/пропорции/FPS |
| Максимальное качество | JPEG normal/high-resolution/maximum-resolution; MediaRecorder sizes, AE FPS, min duration, high-speed, все энкодеры |
| Галерея | Собственный SQLite-индекс; 20 файлов на страницу, миниатюры, фото, кэшированное видео, открытие на телефоне |
| Оригиналы | Канал WLF2: размер, блоки 64 КиБ, SHA-256, подтверждение завершения; лимит 4 ГБ; очистка неполной загрузки |
| Удаление | Только собственные indexed файлы; явное подтверждение на часах |
| Удалённый запуск | Одноразовый ticket от соседнего узла, RemoteActivityHelper, видимое PhoneActivity, обычные разрешения Android |
| Хранение | MediaStore IS_PENDING или SAF tree grant; DCIM/Camera по умолчанию |
| Имена и типы | IMG/VID + локальное время, четыре шаблона, защита от коллизий; JPEG/PNG/WebP, MP4 H.264/HEVC, WebM VP8 |
| Тема | Material You system accent с синей резервной палитрой |
| Диагностика | Полные таблицы API, выбранные размеры, режим снимка при видео, состояние и storage-настройки |

## Архитектура

`core`: независимые Java-классы протокола кадров, журнала команд, математики фокуса, удержания, размеров потока, имён и проверки передачи.

`shared`: JSON-протокол, параметры, PreviewView, иконки и цветовая палитра.

`phone`: CameraEngine на отдельном HandlerThread; CameraService с foreground camera/microphone; отдельный поток JPEG/EGL; последовательный файловый executor; MediaFiles и MediaBridgeService; связанный MediaTransferService для оригиналов.

`wear`: WatchActivity с контрольным heartbeat; MediaClient для запросов галереи/переноса/RemoteActivity; Gallery и RoundHud. Отдельный канал оригиналов не смешивается с каналом живого потока.

## Поведение отказов

Повтор обычной команды использует тот же ID, что исключает повторную фотографию из-за ACK retry. Устаревшие команды (>8 с относительно phoneTime) отклоняются. Сигнал удержания имеет короткую аренду; release помнит ID до запоздалого start. Уход с экрана отменяет серию и загрузки. Потеря часов не останавливает видео на телефоне; доступно уведомление и телефонные кнопки.

Высокое разрешение фото пробуется с предпросмотром; при отказе выбирается следующий размер и публикуется фактический. Для normal video >30 FPS и HS используется PRIVATE SurfaceTexture/EGL, чтобы YUV-поток не ограничивал запись. HS-сессия использует high-speed request list. Если JPEG вместе с видео не поддерживается, фото при записи сохраняет кадр предпросмотра с явным признаком пониженного качества.

Удалённый запуск не обходит блокировку, разрешения или ограничения Android. Tickets живут 5 минут, однократно потребляются; файловый ticket привязан к Wear OS node. Каналы предназначены для соседних сопряжённых устройств.

## Границы версии

Галерея не является общим менеджером всей медиатеки. Нет RAW, HEIF, HDR-видео, фонового запуска скрытой камеры, облачного архива, публикации в Play Store или возобновления частично переданного файла. PNG/WebP — конвертация JPEG. Выбор режима API не гарантирует фактическую частоту при слабом освещении/перегреве. Требуется приёмка на реальных устройствах.
